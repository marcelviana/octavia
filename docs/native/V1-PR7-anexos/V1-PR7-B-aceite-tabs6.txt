PARADA 1 — e a premissa do `pm clear`, que CAIU
==========================================================================
O prompt manda `pm clear` porque "o A2 e o S0 exigem deslogar, e deslogar apaga a sessão".
Deslogar apaga a sessão; `pm clear` apaga tudo o mais junto, e NÃO É PRECISO:

  export function signOutSession(): Promise<void> {
    return signOut(auth)          // apps/native/src/session.ts — não toca o store
  }

CAMINHO USADO, aprovado pelo Marcel em 2026-09-14:
  Metro com EXPO_PUBLIC_DEV_FORGE_401=1 (a E4) + EXPO_PUBLIC_API_BASE_URL=http://localhost:8401,
  e um servidor de host que devolve 401 a toda request (instrumentos/s401.py).
  `adb -s RX2N8000F3D reverse tcp:8401 tcp:8401`.

DECISÃO DO MARCEL, verbatim, e as duas coisas que ele mandou declarar:
  "O custo de login é o mesmo nas duas e a 2 destrói o que não precisa ser destruído — é a
   mesma lição do files-index.json: não apagar estado que o aparelho legitimamente tem, só
   para alcançar um estado de teste."
  1. o 401 forçado exercita o S0 e o RE-login, NÃO a primeira abertura de um app
     recém-instalado. Esse estado continua sem ter sido visto no device, e o `pm clear` só
     chegaria perto dele — não é o suficiente para pagar o cache;
  2. o caminho (FORGE_401 + servidor 401 local) fica REGISTRADO COMO O MÉTODO PADRÃO de
     alcançar o S0 daqui em diante, para que nenhum bloco futuro use `pm clear` por não
     saber que existe alternativa.
