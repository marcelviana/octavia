  => **CONFIRMADO**: os três que podem ficar inertes são `auto-scroll`,

     esquerda. Nenhum dos quatro restantes tem `inativo` em lugar nenhum do
     arquivo. A fronteira por função é a fronteira por estado, agora lida no
     código e não só no dump.

     Uma precisão que o achado do V1 não tinha: o grupo da esquerda tem
     QUATRO (o `tema` é comportamento da tela), e só TRÊS deles podem ficar
     inertes. O `tema` nunca fica. A fronteira de estado é subconjunto da
     fronteira de função, não igual a ela.

     nenhum dos dois:
       LoginScreen.tsx:163   `disabled={!podeEnviar}`          (no Pressable)
       SetlistsScreen.tsx:226 `accessibilityState={{disabled: !podeBaixar}}`

  O `Controle` do palco (StageScreen.tsx:786-828):
  }): React.JSX.Element {
    const estado: EstadoIcone = inativo === true ? 'inerte' : ativo === true ? 'ativo' : 'normal'
    const tinta = inativo === true ? cor.lineInfo : ativo === true ? cor.accent : cor.text
    return (
      <Pressable
        style={({ pressed }) => [
          styles.controle,
          { borderColor: ativo === true ? cor.accent : pressed ? cor.muted : cor.lineInfo },
          ativo === true && { backgroundColor: `${cor.accent}1F` },
          pressed && ativo !== true && { backgroundColor: `${cor.text}14` },
        ]}
        onPress={() => {
          if (inativo === true && motivo !== undefined) onMotivo(motivo)
          onPress()
        }}
        accessibilityRole="button"
        accessibilityLabel={accessibilityLabel}
        testID={testID}
      >
        <Icone nome={icone} tamanho={28} cor={tinta} estado={estado} />
      </Pressable>
    )

  => O `inativo` vira APENAS `estado: EstadoIcone` e `tinta` — desenho. O
     `Pressable` não recebe `disabled`, não recebe `accessibilityState`. Daí o
     `enabled=true clickable=true` que o dump `AVicones-B2-pdf-inertes.xml`
     registrou. **A errata E3 afirma `enabled=false`; o palco tem `true`.**

  POR QUE O S0 SAI `enabled=false` E O PALCO NÃO: o S0 usa `disabled` de
  verdade, e o React Native mapeia `disabled` do Pressable para o
  `AccessibilityNodeInfo.setEnabled(false)` do Android. O palco não o usa.

  O CONSERTO É DE UMA LINHA — E TEM DE SER A LINHA CERTA:

    ✅  accessibilityState={{ disabled: inativo === true }}
    ❌  disabled={inativo === true}

  O `disabled` do Pressable **impediria o onPress**, e o onPress do inerte é o
  que revela o motivo na linha acima da barra:

      onPress={() => { if (inativo === true && motivo !== undefined) onMotivo(motivo); onPress() }}

  Ou seja: usar `disabled` consertaria a árvore e QUEBRARIA o A15 na metade
  que a errata do PRD acabou de fixar ("o motivo é revelado AO TOQUE, por
  MOTIVO_MS = 2500"). É o caso clássico de conserto de uma linha que só é de
  uma linha se for a linha certa — e o CN do aceite tem de mostrar o motivo
  ainda aparecendo DEPOIS do conserto, senão o conserto passou por cima do A15.
