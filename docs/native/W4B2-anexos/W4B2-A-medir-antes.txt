# W3 (div. 129): os gates deixam de só medir.
#
# Até a W2, `gate:a20`, `gate:icones`, G1, G2/G3 e G7 rodavam quando o executor
# os rodava, à mão, e o relatório da PR dizia que rodaram. A disciplina do
# projeto é real e está medida em todas as PRs — e é exatamente por isso que a
# distinção importa: **o gate mede, o gate não IMPEDE**. Nada barrava a entrada
# na `main` de um commit que os reprovasse; o que barrava era alguém ter rodado
# e lido.
#
# Onde cada um passa a rodar (a tabela inteira, com o que fica de FORA e por quê,
# está em `docs/native/W3-anexos/W3-B-os-cinco-gates-e-o-ci.txt`):
#   • `gate:a20` + CN, `gate:icones` + CN  → `apps/native/test/gates.test.ts`,
#     dentro do projeto `native` do Vitest, logo dentro do `pnpm test:unit` do
#     job `build` abaixo. Reprovar = `build` vermelho.
#   • G7 (árvore de trabalho)              → já rodava: ele É
#     `vitest run --project native`, um subconjunto do mesmo `pnpm test:unit`.
#   • G1a/G1b e G2/G3                      → o job `gates-nativos` daqui. São
#     gates DIFERENCIAIS: a verdade deles é um PAR de refs git, não uma árvore.
#     Não cabem num `it` (um teste não sabe qual é a BASE da PR) e precisam do
#     histórico inteiro — por isso job próprio, com `fetch-depth: 0`.
#   • os CN de G1/G2/G3/G7                 → FORA, e declarado: os do G1/G2/G3
#     exigem um par de refs fabricado, e o do G7 TROCA arquivo da árvore de
#     trabalho para rodar o código de ontem contra as asserções de hoje. Um job
#     que muta a própria árvore para provar um ponto é instrumento de mão.
name: CI
'on':
  push:
    branches:
    - main
  pull_request: null
jobs:
  # Os dois gates DIFERENCIAIS. Custam segundos: é `sh`, `git` e `awk`, sem
  # `pnpm install`, sem build. Não têm filtro de caminho de propósito — o
  # escopo do G2/G3 inclui `packages/core/src`, que o `native.yml` não cobre, e
  # numa PR que não toca o nativo os dois passam num diff vazio.
  gates-nativos:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
      with:
        # O histórico inteiro: sem ele não há `merge-base`, e sem `merge-base`
        # não há par. E a HEAD é a do RAMO, não o merge commit que o
        # `actions/checkout` monta por default — senão o que voltou da `main`
        # depois do ponto de ramificação apareceria como diff desta PR.
        fetch-depth: 0
        ref: ${{ github.event.pull_request.head.sha || github.sha }}
    - name: A BASE do par — o ponto de ramificação
      run: |
        set -e
        ALVO="${{ github.event.pull_request.base.sha }}"
        if [ -z "$ALVO" ]; then ALVO=$(git rev-parse HEAD~1); fi
        BASE=$(git merge-base "$ALVO" HEAD)
        echo "BASE=$BASE" >> "$GITHUB_ENV"
        echo "base=$BASE  head=$(git rev-parse HEAD)"
    - name: G1a/G1b — invariância de comportamento e de decisão
      run: sh apps/native/scripts/g1.sh "$BASE" WORKTREE
    - name: G2/G3 — testIDs antes ⊆ depois, linhas de log com errata declarada
      run: sh apps/native/scripts/g2g3.sh "$BASE" WORKTREE
    # W4-b1, div. 223: o registro de integridade dos congelados existia desde a
    # V1-PR2 e nada o lia — o do V1 reprovava desde a V1-PR6 (pelo README, que é
    # o arquivo VIVO das erratas e saiu da lista) sem que ninguém soubesse. Não
    # é diferencial: confere a árvore, não um par. O texto do passo é o mesmo
    # que o `__cn__/cn-w4b1.sh` roda (o CN-223b confere).
    - name: Congelados — shasum -c dos SHA256SUMS do DESIGN-V1 e do DESIGN-N2
      run: |
        F=0
        for d in docs/native/DESIGN-V1 docs/native/DESIGN-N2; do
          echo "== $d"
          (cd "$d" && shasum -a 256 -c SHA256SUMS) || F=1
        done
        exit $F

  build:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    - uses: pnpm/action-setup@v4
    - uses: actions/setup-node@v4
      with:
        node-version: 22
        cache: pnpm
    - name: Install dependencies
      run: pnpm install --frozen-lockfile
    - name: Lint
      run: pnpm lint
    - name: Type-check dos testes (informativo — zerar o passivo e promover a bloqueante, PLANO-TRANSICAO B8)
      run: pnpm exec tsc -p tsconfig.test.json --noEmit
      continue-on-error: true
    - name: Type-check packages/core
      run: pnpm exec tsc -p packages/core/tsconfig.json --noEmit
    # Aqui dentro correm o `gate:a20`, o `gate:icones` e os CN dos dois
    # (`apps/native/test/gates.test.ts`), e o G7 sobre a árvore de trabalho.
    # Este passo NÃO tem `continue-on-error`: um gate que reprova reprova o job.
    - name: Test — a suíte, e com ela os gates embrulhados (W3, div. 129)
      run: pnpm test:unit
    - name: Test coverage
      run: pnpm test:ci
    - name: Upload coverage to Codecov
      if: always()
      uses: codecov/codecov-action@v4
      with:
        file: ./coverage/coverage-final.json
        flags: unittests
        name: codecov-umbrella
        fail_ci_if_error: false
        verbose: true
    - name: Upload coverage artifacts
      if: always()
      uses: actions/upload-artifact@v4
      with:
        name: coverage
        path: coverage
    - name: Build
      run: pnpm build

§1.3 — como o gates-nativos obtém base e head; acesso ao corpo da PR
################################################################################
$ git show origin/main:.github/workflows/ci.yml | sed -n "/gates-nativos:/,/^  build:/p" | grep -n "ref:\|ALVO\|merge-base\|BASE\|WORKTREE"
6:        # O histórico inteiro: sem ele não há `merge-base`, e sem `merge-base`
11:        ref: ${{ github.event.pull_request.head.sha || github.sha }}
12:    - name: A BASE do par — o ponto de ramificação
15:        ALVO="${{ github.event.pull_request.base.sha }}"
16:        if [ -z "$ALVO" ]; then ALVO=$(git rev-parse HEAD~1); fi
17:        BASE=$(git merge-base "$ALVO" HEAD)
18:        echo "BASE=$BASE" >> "$GITHUB_ENV"
19:        echo "base=$BASE  head=$(git rev-parse HEAD)"
21:      run: sh apps/native/scripts/g1.sh "$BASE" WORKTREE
23:      run: sh apps/native/scripts/g2g3.sh "$BASE" WORKTREE

Leitura: checkout com fetch-depth 0 do head.sha da PR (não do merge commit);
BASE = merge-base(pull_request.base.sha, HEAD), ou HEAD~1 no push da main; head =
a árvore de trabalho (WORKTREE). As listas (EXCECOES, PARES_G1B, ERRATAS, REMOCOES)
são lidas do próprio script, no HEAD.

Corpo da PR: o evento pull_request traz github.event.pull_request.body, mas é o
corpo NO MOMENTO DO EVENTO — e um 're-run' reusa o payload original. Ler pela API
(GET /repos/{r}/pulls/{n}) no passo dá o corpo atual. O token default é read, e o
read cobre pull-requests. No push da main não há PR no evento: a PR sai de
GET /repos/{r}/commits/{sha}/pulls (a de merge_commit_sha == sha). Medido:
$ gh api repos/marcelviana/octavia/commits/e9b4196ff/pulls --jq ".[] | {number, merge_commit_sha, body_len: (.body|length)}"
{"body_len":3117,"merge_commit_sha":"e9b41960e4988a4f087c9db66b7486a7956693fe","number":321}

Trailers: o checkout tem o histórico inteiro, então 'git log BASE..HEAD
--format=%(trailers)' seria legível no job. Não é o caminho escolhido (ver o README).
