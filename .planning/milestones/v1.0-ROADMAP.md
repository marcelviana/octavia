## Issues Encountered & Resolutions

### Integration Layer Bug (Phase 2)
**Issue:** Chords sections duplicating during parent re-renders
**Root Cause:** Missing stable key prop causing React to create new component instances
**Resolution:** Added `key={`content-${currentSong}`}` to ContentDisplay
**Impact:** Complete fix with no regressions

### Stale Closure Bug (Phase 3)
**Issue:** Play button non-responsive due to captured state values
**Root Cause:** Inline arrow function with React.memo capturing old isPlaying value
**Resolution:** useCallback with functional update `prev => !prev`
**Impact:** Button fully responsive

### Duplicate Cleanup Hooks (Phase 4)
**Issue:** Two cleanup useEffect blocks with potential race conditions
**Root Cause:** Copy-paste evolution creating redundant cleanup logic
**Resolution:** Consolidated to single cleanup with comprehensive ref nulling
**Impact:** Memory leak prevention verified with extended session tests

### Component Size Violation (Phase 4)
**Issue:** optimized-performance-mode.tsx at 378 lines (252% over limit)
**Root Cause:** Business logic mixed with rendering in monolithic component
**Resolution:** Extracted 5 hooks + 3 sub-components over 3 plans
**Impact:** 149 lines achieved (CLAUDE.md compliant)

## Lessons Learned

### What Went Well
1. **TDD Approach:** Failing tests first provided clear success criteria
2. **Progressive Isolation:** Unit tests isolated root causes effectively
3. **Hook Composition:** Clean separation of business logic from rendering
4. **Automated Verification:** gsd-verifier caught issues before manual testing

### Technical Insights
1. **React Keys Matter:** Stable keys essential for proper component reconciliation
2. **Functional Updates:** `prev => !prev` eliminates closure dependencies
3. **Cleanup Patterns:** Ref nulling prevents memory leaks in long sessions
4. **Component Size Rule:** 150-line limit forces good architecture

### Process Improvements
1. **Wave-based Execution:** Parallelized independent plans within phases
2. **Verification Loop:** gsd-plan-checker caught issues before execution
3. **Incremental Testing:** Tests run after each task for immediate feedback
